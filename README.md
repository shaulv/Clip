# Clip

**A clipboard manager for macOS.** Everything you copy, kept and searchable. A small library of text you reuse. AI that acts at the moment you paste — not in a separate tab.

Menu-bar only. No Dock icon. No account required. Nothing leaves your Mac unless you turn on sync yourself.

## About this project

Clip is a personal project, built and maintained by one person. It is open source under the MIT licence — you can read the code, build from it, fork it, and contribute to it.

**What "open source" means here specifically:**

- The full Swift source is here. Build it yourself with `./build.sh` — no accounts, no tokens, no secrets required.
- One feature is intentionally absent: **Google sign-in / the hosted sync service**. The service runs on the author's own server. Publishing its address would mean every fork of this repository syncing strangers' clipboards into someone else's database. The address is therefore stripped from this tree. Self-hosting is fully documented — see [Sync](#sync) and [docs/SELF-HOSTING.md](docs/SELF-HOSTING.md).
- The app runs **unsandboxed**. This is an honest trade-off, not an oversight — global shortcuts, pasteboard monitoring and pasting into other apps require it. The security implications are spelled out in [SECURITY.md](SECURITY.md).
- There is no roadmap, no milestone tracker, and no guarantee of response time on issues or PRs. Contributions are welcome; turnaround is best-effort.

## Install

### Download the DMG

1. Download **[Clip-2.1.dmg](https://github.com/shaulv/Clip/releases/latest)** from Releases.
2. Open the DMG and drag **Clip** onto **Applications**.
3. **First launch — the unnotarised app warning.** macOS will say it cannot verify the developer.

   This is expected and not a sign anything is wrong. Clip is free and open source; Apple charges $99/year for the Developer ID certificate that would suppress this warning, and this project has chosen not to pay it. The warning fires for every unnotarised app regardless of what it actually does.

   Two ways past it, both one-time:
   - Right-click (or Control-click) Clip in Applications → **Open** → confirm in the dialog
   - In Terminal: `xattr -dr com.apple.quarantine /Applications/Clip.app`, then open normally

   If you would rather not take any of this on trust, the source is right here. Read it, or build it yourself with `./build.sh` — the result is identical to what the DMG contains.

4. Clip will ask for **Accessibility** permission. It needs this to register the global shortcut (⌘⇧Space) and to paste into other apps. It does not ask for, and does not need, anything else.

### Build from source

```bash
git clone https://github.com/shaulv/Clip.git
cd Clip
./build.sh            # builds and launches an unsigned Debug build
```

No package manager step — Clip links nothing but macOS frameworks.

```bash
./build.sh xcode      # open in Xcode instead
./package.sh          # build a signed Release .dmg
./package.sh --install   # build and install to /Applications
```

> **The Xcode project is generated, not committed.** `regen-project.py` writes `Clip.xcodeproj/project.pbxproj` from the files on disk. `build.sh` runs it for you. You never hand-edit the pbxproj.

See [CONTRIBUTING.md](CONTRIBUTING.md) for the full contributor setup guide.

## Features

### History — everything you copy

![Clip's panel showing a clipboard history of text, prompts and an emoji](brand/screenshot-panel.png)

Clip monitors the macOS pasteboard continuously. Every item you copy is stored and classified by kind:

| Kind | What Clip does |
|---|---|
| **Plain text** | Stored as-is; syntax-highlighted if code is detected |
| **Code** | Language detected, shown in the card |
| **Rich text** | Stored with formatting |
| **Emoji** | Recognised and previewed large |
| **Image** | Thumbnail preview; palette extractable |
| **Video** | Stored and previewable |
| **File / Folder** | Stored; path recognised even when copied as text |
| **URL** | Page title fetched, so a link reads as what it points at |
| **Colour** | Hex, RGB and HSL shown inline |
| **Service links** | Figma, GitHub, Slack, and ~12 others — can open in the native app |

**Confidential content is never recorded.** Password managers mark what they put on the pasteboard using `org.nspasteboard.ConcealedType`, `TransientType` and `AutoGeneratedType`. Clip honours all three by default and silently skips those items.

**History is unlimited by default.** Settings → General → History has a cap if you want one.

**Copying the same thing twice keeps one copy.** Clip deduplicates whether the repeat came from this Mac or arrived through sync.

### Library — prompts, notes, skills, designs

Five kinds of item live side by side, each on its own tab:

| Tab | What it holds |
|---|---|
| **Clips** | Your history, newest first |
| **Prompts** | Text you reuse, with `{{variables}}` filled at paste time |
| **Notes** | Written in a full markdown editor |
| **Skills** | Markdown documents with YAML front matter, for AI tooling |
| **Designs** | `DESIGN.md` design systems — Clip can turn these into app themes |

Every tab is yours to configure: show, hide, reorder, and independently set the layout (list or gallery) and density.

#### Prompts and variables

Write a prompt once — `"Translate to {{language}}"` — and Clip fills in the variable at paste time. Variable values are remembered per name, so the second use is usually just Return.

#### Compose-paste

Mark several items across any tab, then paste them as one combined block.

### Search

Search runs over everything at once: title, tags, body, source app, and the date written as you would say it.

```
"yesterday"   →  items from yesterday
"august"      →  items from August
"30/08"       →  items from 30 August
```

Three modes:

| Mode | Behaviour |
|---|---|
| **Contains** | Exact substring match |
| **Fuzzy** | Tolerates typos and partial words |
| **Regex** | Full regular expression |

Results are **ranked**, not merely filtered — the document actually about typography comes first when you search "typography". Typing stays under **3 ms per keystroke** against a 745-item library that includes 74 full design documents.

### Keyboard-first

Open with **⌘⇧Space** (configurable in Settings). The keyboard takes you everywhere from there:

- **Arrow keys** — move through the list
- **Return** — paste the selected item
- **⌥→** — open the action row without lifting your hands
- **Per-item shortcuts** — any item can get its own global shortcut

The panel is an `NSPanel`, not an `NSPopover`. That is why hover actions are reachable from the keyboard. An earlier version used a popover and had six unrelated-looking broken interactions that all traced to one architectural decision.

---

### Paste actions — AI on the way out

The clipboard is the only place on your Mac that sees your work **in transit** — it knows both what you copied and where it is going. Clip's AI acts at that moment.

#### Quick translation — ⌃⌥T

Set two languages in Settings. One keystroke translates in whichever direction the text needs: Clip detects which language it is and gives you the other. No menu, no round trip.

#### Action menu — ⌃⌥A

Opens from **any app**, at the pointer, with no Clip panel on screen:

| Action | What it does |
|---|---|
| Translate | To any configured language |
| Rewrite in a style | Formal, casual, concise, or your own custom style |
| Improve | Tightens and clarifies |
| Fix grammar | Corrects without rewriting |
| Shorten | Cuts to the essentials |
| Bullets | Restructures as a list |
| Summarise | One-paragraph summary |
| Explain error | Reads an error and explains it plainly |
| Convert to JSON | Reformats structured text as JSON |
| Convert to TypeScript type | Generates a TypeScript interface |
| Convert to Swift struct | Generates a Swift struct |
| Write commit message | Reads a diff or description and writes a commit |
| Write reply | Drafts a response |
| Strip secrets | Removes API keys, tokens and passwords before sharing |
| Custom | Any instruction you write |

**Rules that hold everywhere:**
- Nothing on the capture path ever calls a model — copying stays instant, offline and free
- A failed transform **pastes nothing** and leaves your clipboard exactly as it was

**Nine more actions in the detail view** — Improve, Proofread, Title, Tags, Summarise, Explain, Templatise, Translate, Build a theme — each shows a diff before anything is written.

**Bring your own AI provider.** Anthropic, OpenAI, Gemini, Ollama (local), or any OpenAI-compatible endpoint. Keys live in the macOS Keychain. Multiple providers can be configured and given different roles.

### Themes

Twelve built-in themes, light and dark. Every theme is audited for contrast across **43 colour pairings** — a palette that looks fine on a web page cannot ship as an unreadable app.

Three ways to build your own:

| Method | How |
|---|---|
| **Theme builder** | Pick colours directly; live contrast results flag any AAA failure |
| **From a design document** | A `DESIGN.md` with a `colors:` front-matter block already is a theme. Clip maps roles and runs the 43-pairing audit. Of a 74-document test corpus, 65 produce a passing theme; the 9 that cannot say so plainly rather than shipping something unreadable. |
| **From a copied image** | Copy an image; Clip counts pixels and extracts a palette |

---

### Sync

Three methods; one is active at a time. Switching is deliberate.

| Method | What it requires |
|---|---|
| **Sign in with Google** | Nothing — uses the hosted service. **Not available in this open-source build.** |
| **Your own server** | Any PHP 8 host with MySQL. Clip generates the complete setup kit: code, written config, and step-by-step instructions. Your data, your host. |
| **Export and import** | No server. Move a `.clipsync` file between Macs by hand. |

Settings, themes and tab arrangement sync too, on a cadence you choose.

> **Why Google sign-in is unavailable here.** The hosted sync service runs on the author's own server. If its address were published in this repository, every fork would sync strangers into that database without anyone choosing to. The address is therefore stripped from this tree in code, not config — the export script verifies this before allowing a publish. The other two sync methods work fully and are not affected. See [docs/SELF-HOSTING.md](docs/SELF-HOSTING.md) to run your own server.

#### Combining two histories

When you connect a token on a new Mac, Clip asks whether to **combine** or **replace** and shows which way data moves before it moves. Combining does not duplicate: two items with the same content become one that keeps the most configured version — pinned if either was, a title over no title, tags pooled.

### Privacy and security

Clip stores everything you copy, in plain SQLite, on your Mac. That file is treated as the most sensitive thing on the machine.

- **Nothing leaves your Mac** unless you turn on sync — no telemetry, no crash reporting, no analytics, no automatic update check
- **The store is owner-only** — `0600` on the database and its write-ahead log, `0700` on the directories; applied at launch, so an install created with looser permissions is repaired rather than left
- **Confidential content is never recorded** — concealed, transient and auto-generated pasteboard markers are all honoured by default
- **Secrets live in the Keychain only** — no API key, sync token or password reaches preferences, the settings-sync payload, the export file or the logs
- **No third-party code** — nothing to audit, nothing to be compromised upstream
- **The server trusts the token, not the caller** — every row is scoped to a space ID derived from the token, not from the request body; naming someone else's space reaches nothing
- **The QA bridge is compiled out of Release** — the file-driven harness that can drive the app and read its full history exists only when `CLIP_TESTING` is defined; `package.sh` refuses to build a DMG if the symbol is present

**The unsandboxed trade-off stated plainly.** Clip runs unsandboxed, deliberately. The global shortcut, pasteboard monitoring and pasting into other apps all require it — the App Sandbox does not grant that combination. An unsandboxed app has the file access of the user running it. Clip mitigates this by linking no third-party code, making no network request you did not configure, and locking down everything it stores. The trade is real and is stated rather than buried.

Full threat model and evidence for each control: [SECURITY.md](SECURITY.md).

## Testing

Clip uses a file-based probe harness rather than a UI-test framework. The probe writes a command; the app performs it on the main thread exactly as a real event would; the app writes observable state back out.

```bash
# Build the Testing configuration
xcodebuild -project Clip.xcodeproj -scheme Clip -configuration Testing \
  -derivedDataPath build-testing CODE_SIGNING_ALLOWED=NO build

# Start the app under the harness
CLIP_QA=1 CLIP_QA_SANDBOX=1 CLIP_HEADLESS=1 \
  ./build-testing/Build/Products/Testing/Clip.app/Contents/MacOS/Clip &

# Run the probes (on your own Mac, not in CI — they need a real GUI session)
python3 qa-probe.py          # 2,062 behaviour assertions
python3 security-probe.py    # 47 security checks
python3 perf-probe.py        # timings and counters
```

**The XCTest suite** in `ClipTests/` runs unattended in CI (`xcodebuild test`) and covers: hex parsing, the classify ladder, contrast and ThemeRules levels, search modes, migration, time buckets, item merging, file-reference paste, backup manifests, and settings identity.

**The probe suite runs on your Mac, not in CI.** It drives a real launched GUI app — opens the panel, fires global hotkeys, reads what rendered. A GitHub Actions runner does not have that environment. `ci.yml` documents this with a disabled placeholder job rather than pretending the gap does not exist.

**Three things to know before adding an assertion:**

1. **It runs sandboxed.** `CLIP_QA_SANDBOX=1` moves the database, media folder, Keychain service and preferences to a throwaway location. A test cannot damage real data.
2. **The harness is not in the shipped app.** Compiled out unless `CLIP_TESTING` is defined. `package.sh` refuses to build a DMG if the symbol is found in the binary.
3. **Every assertion must be proved able to fail.** Run `--prove` and watch your new check go red before you ship it. This suite has shipped assertions that were vacuously true — a flag set false and never set elsewhere, a cache check that could never trigger. Do not add to that list.

## Self-hosting the sync server

`sync-server-php/` is a PHP 8 + MySQL service with no Composer dependencies. It implements the same API as `sync-server/` (the Python stand-in the probes use).

See [docs/SELF-HOSTING.md](docs/SELF-HOSTING.md) for the full setup walkthrough — about fifteen minutes on any PHP 8 host with MySQL.

```bash
# Test against a local or live deployment
php sync-server-php/test-local.php http://localhost:8080/api
php sync-server-php/test-local.php https://yourdomain.com/api

# Verify no plaintext secrets before deploying
php sync-server-php/check-no-plaintext-secrets.php
```

## Contributing

[CONTRIBUTING.md](CONTRIBUTING.md) has the full setup guide, code conventions, and the detail that follows below.

**Before you open a PR:**

1. `python3 regen-project.py` — regenerate the Xcode project if you added or removed a Swift file
2. `xcodebuild test` — the XCTest suite must pass
3. `python3 qa-probe.py --prove` and `python3 security-probe.py --prove` — run these locally if your change touches the pasteboard, hotkeys, sync, or the theme system; CI cannot run them
4. `python3 docs/generate-counts.py --write` — update the counts in this README
5. One concern per PR — a change that fixes a bug and reformats an unrelated file is two changes

**On response time.** This is a solo project. PRs and issues get attention when they get it; there is no SLA. A PR that passes the tests and follows the conventions stands a good chance of being merged. A PR that does not is more likely to be closed than left open indefinitely.

**On the test bar.** "How do you know this works" is the standard review question. The answer is a measurement or a probe run, not an adjective. See [CONTRIBUTING.md](CONTRIBUTING.md) for what that looks like in practice.

## Security reporting

To report a vulnerability, open a **private security advisory** on this repository — not a public issue. Include what an attacker gains and the smallest reproduction you have. You will get an acknowledgement, and credit unless you would rather not.

Full threat model, controls, and how to verify each one: [SECURITY.md](SECURITY.md).

## The mark

Clip's mark is **⌘C** — the shortcut the whole app is about — in `#8ABDFF` on black.

`brand/clip-mark.svg` is the trademark as drawn. `brand/clip-glyph.svg` is the glyph alone on no background — this is what every derived asset is built from:

```bash
swift brand/make-icons.swift brand/clip-glyph.svg <output-dir>
```

This generates every app icon size and the menu-bar template image from the single vector. The 16 pt icon and the 1024 pt icon are the same drawing, not the same PNG resized.

**On forks and the mark:** the MIT licence covers the code. The mark — the ⌘C glyph and the name "Clip" — is not included in that grant. If you fork and ship something different, call it something different.
